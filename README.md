# kids-group-chat

子どもたちが、URLひとつで入れるチャットの部屋。その部屋にAIが同席する。

AIの立ち位置は部屋ごとに選べる。話し相手になる**会話モード**と、ひとりの参加者としてやり取りを聞いていて
頼まれたときだけ自分の意見を言う**意見モード**の2つ。部屋を作るときに選び、あとから管理画面で変えられる。

設計の背景と仕様は [`kids-group-chat-handoff.md`](./kids-group-chat-handoff.md) を参照。
（`hermes-kids-chat-handoff.md` は Hermes Agent を組み込む前提だった前版で、現在は不採用。）

## 構成

```
.
├── server/   BFF (Node 22 + TypeScript + Hono + SQLite)
├── web/      フロント (Vite + React + TypeScript)
├── deploy/   systemd のユニット、Caddy / nginx の設定例、控えを取るスクリプト
└── docs/     開発と運用の手順
```

サーバーは1台。本番ではフロントの静的ファイルも BFF が配る。

| ドキュメント | 中身 |
|---|---|
| [`docs/development.md`](./docs/development.md) | 手元で動かして直すまで |
| [`docs/deploy.md`](./docs/deploy.md) | サーバーに置いて運用するまで |
| [`docs/update.md`](./docs/update.md) | 直した内容をサーバーに反映するまで |
| [`kids-group-chat-handoff.md`](./kids-group-chat-handoff.md) | 設計の背景と仕様 |

## 動かす

```bash
npm install
cp .env.example .env   # 値を埋める
npm run dev            # BFF (:8787) と Vite (:5173) を同時に起動
npm run typecheck      # server と web の tsc --noEmit
```

`http://localhost:5173` を開く。`.env` の埋め方、部屋を作って2人で通しで動かす手順、疎通確認の
スクリプト、つまずいたときに見る場所は [`docs/development.md`](./docs/development.md)。

AI Engine のトークンは無くても始められる。AIだけが黙って、子ども同士のチャットは動く。

## 部屋を作る

`.env` に `GOOGLE_CLIENT_ID` と `SUPER_ADMIN_EMAILS` を設定し、ブラウザで `/admin` を開いて
Googleアカウントでログインする。部屋の作成・一覧・設定変更・ログ閲覧・参加者の強制退出・削除は
ここでできる。

ログインできるのは、あらかじめ登録されたアカウントだけ。詳しくは[管理画面](#管理画面)。

コマンドからも作れる（`npm run room:new -w server`）。オプションは
[`docs/development.md`](./docs/development.md#4-通しで動かしてみる) にある。

## 部屋に入る

入り方は2つある。どちらでも同じ部屋に入る。

- **部屋コード**: トップページ（`/`）で6桁の数字を入れる。黒板に書いたり読み上げたりして渡す
- **URL**: `/r/<22文字のID>` を直接開く。QRコードやチャットで渡す

コードは部屋を作ったときに自動で採番され、管理画面の一覧と詳細に出る。「コードをコピー」で
その6桁だけを取れる。期限が切れた部屋のコードは引けなくなり、また別の部屋で使われる。

当てずっぽうで他人の部屋に入られないよう、コードの照会はIPごとに毎分10回までに絞ってある
（`server/src/config.ts` の `rateLimits.roomCodeLookupsPerMinute`）。人に見られたくない部屋には、
合言葉も設定しておく。

## 使うモデル

フェーズ1で3つ試して `preview/Qwen3-VL-30B-A3B-Instruct` に決めた。

| | gpt-oss-120b | preview/Qwen3-VL-30B | llm-jp-3.1-8x13b |
|---|---|---|---|
| 最初のチャンクまで | 1.3秒 | 0.3秒 | 0.4秒 |
| 子ども向けの日本語 | 自然・短め | 自然・短め | 講義口調で758文字 |
| 誰に返すかの判断 | 3人全員に返した | 呼びかけた子だけに返した | － |
| 画像入力 | 読めない | 読める | － |

`llm-jp` は system prompt をほとんど守らなかった。`gpt-oss-120b` は正式提供で品質も十分だが、
宛先を絞れず画像も読めないので、フェーズ5の添付を考えると preview 版を採る。preview が廃止
されたら `gpt-oss-120b` に戻し、画像はファイル名だけ伝える方式に切り替える。

`gpt-oss-120b` の画像は注意がいる。`image_url` を送っても HTTP 200 が返るので対応して
いるように見えるが、本文は「画像が確認できません」になる。疎通スクリプトはステータスでは
なく応答本文で判定している。

Qwen3-VL は履歴の「なまえ: 本文」という形を真似て、自分の返事にも `はなこ: ` と接頭辞を
付けてくる。画面には発言者名が別に出るので、`stripSpeakerPrefix` で落としている。落とすのは
履歴にある発言者名と `AI` だけなので、`ヒント: ` のような本文は残る。

同じように、`**つよい**` のような Markdown の飾りも出てくる。画面は本文をそのまま文字として
出すので、記号が生で子どもに見えてしまう。system prompt で「記号でかざらない」と書いたうえで、
`plain-text.ts` のフィルタでも落としている。落とすのは `**` `__` と行頭の見出し記号だけで、
行頭の `- ` は `・` に変える。単独の `*` は `2*3` のような本文を壊すので残す。
フィルタはストリーミング中に1文字ずつ動き、判定がつかない末尾だけを次の差分まで持ち越す。

### モードでモデルを変える

意見モードは向くモデルが違う。Qwen3-VL は速いが、意見ではなく全員の発言を順番に要約してしまう。
意見から書きはじめたのは `preview/gemma-4-31B-it` だけだった（Kimi-K2.6 は書けるが40〜66秒かかる）。

そこで意見モードだけ `.env` の `SAKURA_AI_MODEL_OPINION` で差し替えられるようにしてある。未設定なら
`SAKURA_AI_MODEL` と同じものを使う。会話モードは常に `SAKURA_AI_MODEL`。

gemma-4 は画面に出る見出しを本文の1行目にも書いてしまう（ほぼ毎回「AIの いけん」から始める）。
見出しだけの行なら `stripSpeakerPrefix` で落としている。

### 部屋ごとに中身を変える

`.env` が決めるのは既定だけで、モデルと system prompt は部屋ごとに差し替えられる。
会話モードと意見モードで別々に持つので、モードを切り替えても、それぞれの設定は残る。

| | 部屋で指定したとき | 指定しないとき（既定） |
|---|---|---|
| モデル | `chat_model` / `opinion_model` | `.env` の `SAKURA_AI_MODEL` / `SAKURA_AI_MODEL_OPINION` |
| system prompt | `chat_system_prompt` / `opinion_system_prompt` | `prompt.ts` の `KIDS_SYSTEM_PROMPT` / `OPINION_SYSTEM_PROMPT` |

DBの列はどれも NULL 可で、NULL が「既定のまま」を意味する。解決は `lib/ai-settings.ts` の
`resolveAiSettings()` 1か所に寄せてある。管理画面では空欄が NULL にあたり、いちど書いたものを
空にすれば既定に戻る。

モデルの選択肢は AI Engine の `/models` から引く（サーバー側で5分キャッシュ）。一覧には埋め込みや
音声認識のモデルも混ざるが、レスポンスに種別が付かないので名前で落としている。一覧を取れない
ときは、モデル名を直接入力する形に切り替わる。

system prompt は4000文字まで。既定のプロンプトは管理画面の「既定を読み込んで編集する」で
textarea に流し込める。

## AIのモード

部屋ごとに `aiMode` を持つ。どちらを選んでも、子ども同士のチャットは同じように動く。

| | 会話モード (`chat`) | 意見モード (`opinion`) |
|---|---|---|
| AIの立ち位置 | 部屋の話し相手 | ひとりの参加者として自分の意見を言う。会話には割り込まない |
| AIが口を開くきっかけ | 入力欄の「🤖 AIに きく」／本文が `@AI` で始まる／部屋が「毎回返す」(`replyMode: always`) | タイムラインの下の「🤖 AIに いけんを きく」だけ |
| 発言との関係 | 発言に対して返事をする | 発言では動かない。ボタンは発言を伴わない |
| 画面での見出し | `AI` | `AIの いけん` |
| 誰に向けて話すか | 呼びかけた子ひとり | 部屋のみんな |

意見モードでは、AIが口を開いたことが部屋の全員に見えるよう、意見の前に「◯◯さんが AIに いけんを
ききました」を出す。

意見が毎回まっさらから始まらないよう、意見モードの履歴は前回までの意見で区切って渡している
（区間ごとのやり取りを1つの `user` に、そのあとの意見を `assistant` に）。過去の意見を自分の言葉として
見たうえで、その続きを書かせるため。

`replyMode`（呼ばれたら返す／毎回返す）は会話モードのときだけ効く。意見モードでは使わないので、
管理画面でも出てこない。

同時に走る生成は、どちらのモードでも部屋に1本まで。ほかの子が呼びかけた場合は断る。生成中は
「とめる」ボタンが出て、押すとそこまでの本文を残して終わる。`SAKURA_AI_TOKEN` が未設定なら、
AIは黙ったまま子ども同士のチャットだけが動く。

## 添付ファイル

入力欄の「📎 ファイル」から付ける。1回の発言に3つまで、1ファイル10MBまで。

| 種類 | 画面 | AIへの渡し方 |
|---|---|---|
| 画像 (png / jpg / gif / webp) | タイムラインに表示 | いちばん新しい1枚だけを `image_url` で渡す |
| テキスト (txt / md / csv) | ファイル名のリンク | 中身を1万文字まで本文に添える |
| PDF | ファイル名のリンク | ファイル名だけ（テキスト抽出は未実装） |

拡張子の allowlist 方式で、表にない種類は受け付けない。種類の判断はブラウザが送ってくる
Content-Type ではなく拡張子で行い、配信するときも allowlist で決めた MIME を返す。画像以外は
`Content-Disposition: attachment` にして、ブラウザで開かせずに保存させる。

送信の流れは2段階になっている。

1. `POST /api/rooms/:id/attachments` でファイルだけ先に送る（この時点では上げた本人にしか見えない）
2. `POST /api/rooms/:id/messages` に `attachmentIds` を入れて発言する

送る前なら `DELETE /api/rooms/:id/attachments/:attachmentId` で取り消せる。取り消さないまま
放置されたものは、次の誰かのアップロード時に、6時間を過ぎていれば実体ごと片づける。

画像は1枚でもトークンを大きく食うので、AIに渡すのは履歴の中でいちばん新しい1枚だけにしている。
4MBを超える画像は渡さず、ファイル名だけ伝える。

## 管理画面

`/admin`。大人が見る画面なので、文言はひらがな寄りにしていない。

### ログインと権限

Googleアカウントでのログインが必須で、入れるのはサーバー側に登録したアカウントだけ。

| | 特権管理者 | 管理者 |
|---|---|---|
| 決まり方 | `.env` の `SUPER_ADMIN_EMAILS` | 特権管理者が管理画面から登録 |
| 見える部屋 | すべて（誰の部屋かも一覧に出る） | 自分が作った部屋だけ |
| アカウントの登録・無効化・削除 | できる | できない |

特権管理者だけは事前登録なしでログインでき、初回ログイン時にアカウントが自動で作られる。
まっさらな状態からでも、まず特権管理者が入り、そこから他の管理者を登録していける。

権限は毎回 `.env` と突き合わせるので、`SUPER_ADMIN_EMAILS` から名前を外して再起動すれば、
その人は普通の管理者に戻る（DBに権限は持たせていない）。

他の管理者が作った部屋は `404` で返す。`403` にすると、部屋IDを当てずっぽうに叩くだけで
部屋の有無が分かってしまうため。

セッションは HttpOnly cookie で持ち、既定で12時間（`ADMIN_SESSION_TTL_HOURS`）で切れる。
アカウントを無効化・削除すると、開いているセッションもその場で切れる。

特権管理者とログイン中の自分自身は、管理画面から無効化も削除もできない。誰も入れない状態を
その場で作れてしまうため。特権管理者を辞めさせるときは、先に `.env` の `SUPER_ADMIN_EMAILS`
から外して再起動する。外したあとは、ただの管理者として無効化も削除もできる。

管理者アカウントを削除しても、その人が作った部屋は消えない。所有者なしの部屋として残り、
以後は特権管理者だけが管理できる。フェーズ8以前から残っている部屋も同じ扱いになる。

### できること

| できること | 補足 |
|---|---|
| 部屋の作成 | 名前・合言葉・定員・AIに聞ける回数・有効時間・AIのモード・返し方（会話モードのときだけ）・モデル・system prompt |
| 一覧 | 残り時間、在室数、発言数、AIの使用量（`turnsUsed / turnLimit`）、URLのコピー。特権管理者には作った管理者のメールアドレス（所有者なしの部屋は「所有者なし」）も出る |
| 設定変更 | 名前・定員・AIに聞ける回数・AIのモード・返し方・モデル・system prompt。合言葉と期限は変えられない（期限は「4時間 延長」） |
| ログ閲覧 | 直近500件。発言者・時刻・本文・添付のファイル名。NGワードに当たった行には「要確認」が付く |
| エクスポート | 部屋・参加者・全メッセージをJSONで保存 |
| 強制退出 | 押し間違い防止に2回押させる。確認ダイアログは出さない |
| 削除 | 論理削除。会話ログはDBに残り、添付ファイルは実体ごと消える |
| アカウントの登録 | 特権管理者だけ。メールアドレスを登録すると、その人がログインできるようになる |
| アカウントの無効化 | 特権管理者だけ。行は残るので、あとから有効に戻せる |
| アカウントの削除 | 特権管理者だけ。押し間違い防止に2回押させる。その人の部屋は所有者なしで残る |

強制退出は `participants.kicked_at` に印を付ける。cookie が残っていても `403 kicked` で戻れず、
開いている画面はサーバー側から SSE を切って「この へやから でました」に差し替える。名前の行は
消さないので、同じ名前で入り直すこともできない。

部屋を消すと添付ファイルは戻らない。ログが要るなら先にエクスポートしておくこと。

## レート制限

| 単位 | 上限 | 超えたとき |
|---|---|---|
| 参加者ごとのAIへの呼びかけ | 毎分3回 | その発言は残り、AIだけが返事をしない |
| 参加者ごとの発言 | 毎分20回 | `429 too_fast` |
| 部屋ごとのAIへの呼びかけ | `turnLimit`（既定100回） | 管理画面で上限を上げれば続きから使える |

参加者ごとの制限はプロセス内メモリの直近1分の窓で数える。サーバーは1台なので分散は考えない。
再起動すると窓は消えるが、1分ぶんなので実害はない。部屋ごとの上限だけはDBの `turns_used` が持つ。

断る判定は、数を消費しないものから順に見る。「AIが混んでいて断られた」ぶんで参加者の枠や部屋の
ターンが減らないようにするため。

## NGワード

発言に引っかかる語が入っていると、次の2つだけが変わる。

- AIがその話に触れない。会話モードではその発言に返事をせず、意見モードでは前回の意見より
  あとに印の付いた発言があるあいだ、意見を言わない（頼んだ子の画面にだけ理由が出る）
- 管理画面のログに「要確認」の印が付く

発言そのものは、ふつうに部屋へ出る。大人が同じ部屋にいて声をかけられる状態を前提にしているので、
会話を止めるより、見えたまま印が残るほうが扱いやすい。印が付いたかどうかは子どもの画面に出さない。
見えると、印を付けさせる遊びが始まるため。

判定は、全角と半角・カタカナとひらがな・あいだに挟んだ記号を畳んでから、部分一致で見る。
空白は畳まない。「し ね」のような書き方は拾えなくなるが、畳むと「わたし ねむい」まで引っかかる。

既定のリストは `server/src/lib/word-filter.ts` にある出発点でしかない。集まる子どもと場に合わせて、
`.env` の `NG_WORDS_FILE` にファイルのパスを書いて差し替える（1行1語、`#` から先はコメント）。

これは最後の網ではない。止められないものが残る前提で、大人が同席して運用する。

## 子ども向けの画面

フェーズ7で、実際に触ってもらう前提の調整を入れた。

| | |
|---|---|
| だれの発言か | 色と位置に加えて、発言の頭のマーク（自分 🙂／ほかの子 🧒／AI 🤖）でも分かるようにした |
| タイムライン | 上に戻って読んでいるあいだは下へ引っぱらない。離れているときは「↓ あたらしい はなし」が出る |
| 入力欄 | 入力欄を全幅にして、ボタンは下に1段。320px幅の画面でも3つが1行に収まる |
| 在室者 | 人数を先に出し、名前は横に流す。人が増えてもヘッダーが縦に伸びない |
| 「でる」 | 押し間違い防止に2回押させる。5秒さわらなければ元に戻る |
| 読み上げ | エラーは `role="alert"`、お知らせと「かんがえちゅう」は `role="status"` |

## 本番に置く

手順は [`docs/deploy.md`](./docs/deploy.md) にまとめてある。1コア/1GB の Ubuntu 1台に、
アプリを `/opt/kids-group-chat`、データを `/var/lib/kids-group-chat` に置く形。

```bash
npm ci && npm run build   # web/dist と server/dist を作る
npm start                 # node server/dist/index.js
```

`NODE_ENV=production` にすると、cookie に `Secure` が付き、`GOOGLE_CLIENT_ID` と
`SAKURA_AI_TOKEN` の欠け、`SUPER_ADMIN_EMAILS` が空のままなのを起動時に弾く。フロントの静的ファイルは同じポートから BFF が配るので、
Webサーバー側に置くものは無い。

HTTPS を終端するときに押さえるのは2つだけ。SSEをバッファさせないこと（溜めて送られると、AIの
返事がまとめて一気に出る）と、アップロードのサイズ上限を上げること（nginx の既定 1MB だと添付が
413 になる）。`deploy/Caddyfile` と `deploy/nginx.conf` はどちらもそれを入れてある。

`systemctl restart` で送られる SIGTERM を受けたら、生成中のAIの返事を中断してそこまでの本文を
保存し、開いているSSEを閉じてからDBを閉じて終わる。
